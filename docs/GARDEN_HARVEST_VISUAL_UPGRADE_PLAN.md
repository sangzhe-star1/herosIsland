# 菜园与丰收视觉/体验升级任务计划

> 基线：2026-09-05。面向 5–8 岁男孩子；优先让孩子一眼看懂“现在要做什么”，再增加岛屿的探索感和成就感。

## 本轮目标与边界

- **三秒规则**：进菜园、进入丰收关后，三秒内能找到当前唯一的主要动作；图标优先于文字。
- **少年英雄农场，而不是信息面板**：地、工具、伙伴、订单和奖励要像可探索的冒险基地，而不是一排冷冰冰的数值卡。
- **复用优先**：继续扩展 `UiKit`、`Palette`、`ScreenFit`、`Juice`、`FarmWorld`、`PlotView`、`HarvestAction` 和 `TutorialDirector`。不新建平行 UI、库存、手势或存档系统。
- **可访问性不倒退**：保留单手指操作、大点击热区、语音/图形提示和低动态设置；16:9 与 4:3 都必须能玩。

本计划不在第一轮更换玩法结构、不一次性导入大量陌生美术，也不把像素风素材和当前软描边卡通素材直接混用。

## 本轮大版本：英雄基地 HUD 与场景分区（已完成）

> 本节是本轮的执行清单，不以文档中的描述替代代码、探针和双尺寸截图验收；未勾选项目均视为尚未完成。

### 目标

- **让菜园先像一座基地，再像一张操作页**：把可见世界组织成“左侧英雄补给区—中央菜畦行动区—右侧探索/扩建区”，孩子进入页面时应先看到自己的岛，而不是被顶栏和底栏夹住的一块空地。
- **把 HUD 收成三个容易扫读的区域**：顶部只承担返回、等级、菜园名称、挑战和货币；底部把蓝色工具区、金色的唯一主任务、绿色种子区分开；仓库和装饰册保留为安静的功能入口。
- **保留现有玩法和事件来源**：播种、照料、收菜、订单、每日奖励、存档、镜头聚焦、鼠标/触摸路径仍由 `GardenScreen`、`FarmWorld`、`PlotView`、`HeroTaskRibbon` 和既有管理器负责。视觉层不能生成第二份任务、背包或命中规则。
- **释放真正可玩的世界面积**：压缩冗余的栏位高度，但不缩小孩子实际点击热区；16:9 与 4:3 下都要同时看得到当前目标、可操作地块和主要工具。

### 设计原则

1. **基地分区优先于零散装饰**：先用大而低对比的草地、路径和地形把区域读出来，再补少量树、篱笆、石头和蕨类；不能用一堆小物件填满空白。
2. **一处金色，其他各司其色**：金色只提示“现在要做什么”；工具使用稳定蓝色，种子使用绿色，仓库/挑战使用中性暖色，避免每个按钮都高亮。
3. **从功能地点长出提示**：订单、仓库、扩建和主任务优先关联现有建筑/地块与世界旗标；静态场景装饰必须在目标安全区之外并且完全透传输入。
4. **字和图标永远不抢位置**：标题使用真实木牌/面板承载，正文保持深色清晰字体；图标与文字、相邻操作区之间预留明确空隙，禁止靠压缩字号或负间距塞内容。
5. **扩展现有组件，不复制系统**：HUD 外观复用 `UiKit`、`Palette`、`ScreenFit`、`Juice` 和 `HeroTaskRibbon`；世界装饰只作为 `FarmWorld` 的被动绘制层，继续通过 `PlotView`/既有设施命中测试响应操作。

## 视觉方向：少年英雄探索农场

关键词是 **明亮、厚实、会回应、值得收集**：草地有层次，地块像能升级的据点，工具像小伙伴，完成订单有清楚的“我帮到了谁”。

1. **一个主焦点**：页面只保留一个高对比主任务条（例如“给番茄浇水”或“完成这张订单”）；其他状态退为安静的徽章。
2. **两级描边和三级深度**：交互物用较深蓝绿描边与短阴影，普通背景仅用浅边或纹理；避免所有卡片同样粗、同样亮。
3. **从地图长出 UI**：订单、仓库、厨房等入口优先绑定现有建筑或世界坐标，而不是继续叠加漂浮按钮。
4. **每次动作有去向**：浇水有水滴和恢复色；收菜飞向仓库或溢出篮；交单有顾客表情、进度勾和奖励落点。
5. **控制认知负担**：底部工具仅展示此刻有用的 3–4 个；种子、扩建等放入明确入口或按阶段露出，不能让一排小图标争抢注意力。

当前要先解决的是**风格不统一**，而不是盲目加素材：程序绘制的世界/UI、粗深描边的作物贴纸、狗和部分建筑来自不同视觉语言；菜园的前 6 种作物还通过 `IconLibrary`，后 8 种与丰收页直接读取 PNG。之后应让两页的同种作物走同一资源映射和同一显示规范。

## 素材策略

### 先用现有素材，先统一再扩充

项目已有作物、角色、背景、图标和特效素材，第一步是把它们收进同一套色板、描边、投影和尺寸规范。优先做一张小样板：**一座菜园建筑、两种作物的三个生长状态、两张任务卡、一个底部工具按钮**。小样通过截图验收后，再批量替换。

### 可选外部素材：仅作补充，先做风格试片

- [Kenney Tiny Farm](https://kenney.nl/assets/tiny-farm) 是 CC0 的 16×16 农场素材，适合参考布局、做低成本原型或提取“道路/围栏/道具”种类清单；它是像素风，**不能直接和当前软描边卡通混贴**。
- [Kenney Animal Pack Remastered](https://kenney.nl/assets/animal-pack-remastered) 可作为小动物、访客姿态的候选来源；导入前先做统一色板、大小和轮廓试片。
- [Kenney UI Pack](https://kenney.nl/assets/ui-pack) 只参考控件构成，不作为默认界面皮肤，以免和项目现有 UI 语言冲突。Kenney 说明其资产采用 CC0、可商用且无需署名；每次实际导入仍要记录具体来源与许可证。[说明](https://kenney.nl/support)
- [Kenney Nature Kit](https://kenney.nl/assets/nature-kit) 和 [Kenney Food Kit](https://kenney.nl/assets/food-kit) 更适合补足道路、围栏、石头、容器等物件的构图参考；同样先做风格试片，而不是整包混入。

### 适合生成的专属素材

后续可用生成工具一次产出同一风格的“菜园扩展包”：小屋/水井/围栏/路牌/旗帜、草地与泥土纹理块、浇水和交单小特效、工具人格化图标。生成前固定样式卡：柔和 2D 贴纸感、深蓝绿外轮廓、饱和但不过荧光、浅暖色阴影、透明背景、以 1280×720 下 48–96px 的可读性为验收尺寸。不要逐张随机生成后混入。

实际导入外部或生成素材时，在 `docs/ASSET_ATTRIBUTION.md` 记录来源、许可、原始尺寸、压缩尺寸和使用页面。

## 每次迭代的交付门槛

1. 先复用组件并写清数据/事件从哪里来；若确需新增组件，必须能在菜园和丰收至少两处复用，或说明为什么只能一处。
2. Godot 探针使用独立 `user://` 沙盒，**串行**运行，不能和其他探针共用存档。
3. 运行相关逻辑、触控和静态检查；视觉改动额外生成 16:9 与 4:3 截图。
4. 不以“增加更多按钮/更多文字”解决看不懂的问题；先改图标、位置、对比度、动作和反馈。
5. 每个实际引入的外部素材都可追溯，且在目标尺寸下风格一致。

## 推荐实施顺序

`P0 可信赖 → P1 看得懂 → P2 有自己的基地 → P3 玩得会 → P4 扩素材与观察验证`。

这样不会在奖励与引导尚不可靠时先做大批美术替换，也能让每一阶段独立截图、测试、回滚和验收。
