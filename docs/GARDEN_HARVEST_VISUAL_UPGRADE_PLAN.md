# 菜园与丰收视觉/体验升级任务计划

> 基线：2026-09-05。面向 5–8 岁男孩子；优先让孩子一眼看懂“现在要做什么”，再增加岛屿的探索感和成就感。

## 本轮目标与边界

- **三秒规则**：进菜园、进入丰收关后，三秒内能找到当前唯一的主要动作；图标优先于文字。
- **少年英雄农场，而不是信息面板**：地、工具、伙伴、订单和奖励要像可探索的冒险基地，而不是一排冷冰冰的数值卡。
- **复用优先**：继续扩展 `UiKit`、`Palette`、`ScreenFit`、`Juice`、`FarmWorld`、`PlotView`、`HarvestAction` 和 `TutorialDirector`。不新建平行 UI、库存、手势或存档系统。
- **可访问性不倒退**：保留单手指操作、大点击热区、语音/图形提示和低动态设置；16:9 与 4:3 都必须能玩。

本计划不在第一轮更换玩法结构、不一次性导入大量陌生美术，也不把像素风素材和当前软描边卡通素材直接混用。

- [x] 交单回归改为“交付 → 关闭页面 → 重载 → 重开”的真实路径，验证订单、星星币和木板都已落盘。
- [x] 4:3 丰收挑战卡的可见高度与点击高度统一；窄屏隐藏会压住菜地的下一作物浮层，保留其数据节点以便测试。
- [x] 菜园的 16:9 / 4:3 截图与相关逻辑、触控探针已重新验证。
- [x] 低动态丰收路径补齐：教程把既有手势轨迹固定显示，手持作物直接落到托盘高亮态，篮子以固定勾表示收纳；没有新增另一套教程、手势或目标解析。
- [x] 满仓收菜改为真实回执：`Barn.store_harvest()` 的 `stored / spilled` 分成两段飞行，分别落到仓库入口和可见溢出篮；同一笔刷收多株菜时，所有溢出反馈都稳定落到同一个篮口。
- [x] 教程手势改为一套接触锚定的卡通手：`IconLibrary.guide_hand()` 负责指尖、手掌、拇指和蓝色英雄袖口，`UiKit.guide_hand()` 让丰收教程、冒险提示和技能栏共用；所有调用方只放置真实触点，不再各自猜偏移量。
- [x] 主任务条收口为 `HeroTaskRibbon`：菜园继续独占任务优先级、订单数据和镜头聚焦；组件只组合大图标、一步动作、订单进度与可点击外观。宽屏和 4:3 紧凑布局共用同一组件，不再有第二份任务判断或按钮样式。
- [x] 每日三枚徽章与金色好运可见化：`FarmDailyManager` 的唯一 `all_done()` 派生同时驱动任务条和既有 4% → 8% 金色概率；三项做完才显示金色火花与“好运 ×2”，不新增签到、货币或必出奖励。
- [x] 世界主任务旗标：同一份 `_next_task()` 同时喂给 `HeroTaskRibbon` 和 `FarmWorld`；可行动的地块/订单板获得同色小旗，打开面板、无任务或只在生长时自动清除，旗标不接输入。

## 当前问题与优先级

| 优先级 | 问题 | 对孩子的影响 | 本轮处置 |
| --- | --- | --- | --- |
| P0 | 每日任务的 `date / progress / claimed` 曾会在存档标准化后丢失 | 重开后奖励和进度看起来“被吃掉” | 补默认字段，并用真实保存/重载探针验证 |
| P0 | 交单后的重载回归仍有失败 | 孩子看到奖励后重开，可能觉得奖励不可信 | 修正触控探针的隔离与断言，验证金币和木板 |
| P1 | 丰收复杂手势的教学轨迹与真实识别规则不一致 | 照着手指做仍失败，挫败感很强 | 让教程复用同一份手势路径/识别参数 |
| P1 | 满仓时收获动画曾始终飞向仓库 | 看见菜进仓，实际却进了溢出篮，因果不清楚 | 已读取现有收获回执，按真实目的地拆分飞行 |
| P1 | 菜园仍偏平、工具区和卡片信息密集 | 视觉焦点分散，像原型而不像自己的基地 | 先建立统一视觉层级和场景装饰组件 |

## 视觉方向：少年英雄探索农场

关键词是 **明亮、厚实、会回应、值得收集**：草地有层次，地块像能升级的据点，工具像小伙伴，完成订单有清楚的“我帮到了谁”。

1. **一个主焦点**：页面只保留一个高对比主任务条（例如“给番茄浇水”或“完成这张订单”）；其他状态退为安静的徽章。
2. **两级描边和三级深度**：交互物用较深蓝绿描边与短阴影，普通背景仅用浅边或纹理；避免所有卡片同样粗、同样亮。
3. **从地图长出 UI**：订单、仓库、厨房等入口优先绑定现有建筑或世界坐标，而不是继续叠加漂浮按钮。
4. **每次动作有去向**：浇水有水滴和恢复色；收菜飞向仓库或溢出篮；交单有顾客表情、进度勾和奖励落点。
5. **控制认知负担**：底部工具仅展示此刻有用的 3–4 个；种子、扩建等放入明确入口或按阶段露出，不能让一排小图标争抢注意力。

当前要先解决的是**风格不统一**，而不是盲目加素材：程序绘制的世界/UI、粗深描边的作物贴纸、狗和部分建筑来自不同视觉语言；菜园的前 6 种作物还通过 `IconLibrary`，后 8 种与丰收页直接读取 PNG。之后应让两页的同种作物走同一资源映射和同一显示规范。

## 素材策略

### 先用现有素材，先统一再扩充

项目已有作物、角色、背景、图标和特效素材，第一步是把它们收进同一套色板、描边、投影和尺寸规范。优先做一张小样板：**一座菜园建筑、两种作物的三个生长状态、两张任务卡、一个底部工具按钮**。小样通过截图验收后，再批量替换。

### 可选外部素材：仅作补充，先做风格试片

- [Kenney Tiny Farm](https://kenney.nl/assets/tiny-farm) 是 CC0 的 16×16 农场素材，适合参考布局、做低成本原型或提取“道路/围栏/道具”种类清单；它是像素风，**不能直接和当前软描边卡通混贴**。
- [Kenney Animal Pack Remastered](https://kenney.nl/assets/animal-pack-remastered) 可作为小动物、访客姿态的候选来源；导入前先做统一色板、大小和轮廓试片。
- [Kenney UI Pack](https://kenney.nl/assets/ui-pack) 只参考控件构成，不作为默认界面皮肤，以免和项目现有 UI 语言冲突。Kenney 说明其资产采用 CC0、可商用且无需署名；每次实际导入仍要记录具体来源与许可证。[说明](https://kenney.nl/support)
- [Kenney Nature Kit](https://kenney.nl/assets/nature-kit) 和 [Kenney Food Kit](https://kenney.nl/assets/food-kit) 更适合补足道路、围栏、石头、容器等物件的构图参考；同样先做风格试片，而不是整包混入。

### 适合生成的专属素材

后续可用生成工具一次产出同一风格的“菜园扩展包”：小屋/水井/围栏/路牌/旗帜、草地与泥土纹理块、浇水和交单小特效、工具人格化图标。生成前固定样式卡：柔和 2D 贴纸感、深蓝绿外轮廓、饱和但不过荧光、浅暖色阴影、透明背景、以 1280×720 下 48–96px 的可读性为验收尺寸。不要逐张随机生成后混入。

实际导入外部或生成素材时，在 `docs/ASSET_ATTRIBUTION.md` 记录来源、许可、原始尺寸、压缩尺寸和使用页面。

## 分期任务

### Phase 0：可信赖的循环（先完成）

- [x] **P0-1 每日任务存档往返**：保留 `farm.dailies` 默认字段；探针走 `RewardManager.grant()` → `SaveManager.save_game()` → `load_game()`，确认同日进度、已领标记和二次领奖幂等。
- [x] **P0-2 交单重载回归**：隔离测试存档，交单后重载，确认星星币、木板与已交付订单均准确；不要把未保存的测试清理操作写回断言目标。
- [x] **P0-3 探针整合**：丰收门已断言新存档的首关作物、真实按键进入下一未完成关，以及全通关时的星标预览；覆盖线按实际执行数维持双尺寸验证。

验收：静态检查零 error；四个独立探针串行通过；每日奖励和交单奖励在重开后都不重复、不丢失。

### Phase 1：视觉骨架与信息层级

- [x] **P1-1 主任务条**：`HeroTaskRibbon` 以任务图、一步动作、进度和可点击聚焦组成唯一主焦点；菜园仍通过 `_next_task()` / `_focus_next_task()` 提供唯一数据与行为来源，16:9 / 4:3 真实触控已验证不遮挡地块、工具、仓库或装饰入口。
- [x] **P1-1a 每日成就提示**：`HeroTaskRibbon` 只接收 `FarmDailyManager.summary()` 的展示数据；未完成显示三颗小星与 `n/3`，完成后让既有金色概率提示为“好运 ×2”。领取奖励与否不改变完成语义，避免 UI 与种植概率分叉。
- [ ] **P1-2 头/底栏收拢**：顶部只留返回、当前目标与必要货币；底栏改为“唯一主行动 + 展开工具”，让“下一步”成为唯一金色焦点。丰收把订单收进一块订单夹，目标篮用更大的作物样本和静态底座表达。
- [x] **P1-2a 窄屏下一步**：4:3 / tall 布局把既有 `NextTask` 放到工具栏右侧空位；宽屏保留原位，两种布局共用同一任务推导、聚焦和 `UiKit` 组件。
- [ ] **P1-3 深度规范**：把卡片、按钮、地块、可点击建筑归到两级描边和三级阴影；先在菜园和市场各落一屏小样。
- [x] **P1-3a 菜畦岛小样**：复用 `Shapes.blob()`、`FarmWorld` 和 `PlotView`，以稳定的草缘、松土短垄和低对比清理区替代深褐色木箱地块；16:9、4:3 均已截图复验。
- [ ] **P1-4 市场重排**：复用现有货品、步进器和确认逻辑；缩减空白、改为商品卡和清晰的结算区，不再新建购买系统。
- [ ] **P1-5 作物资源映射统一**：让菜园和丰收通过相同的路径/显示规则取同一种作物；`UiKit.picture()` 承接纹理，逻辑和作物数据不重复维护。

验收：5 秒截图测试中，孩子能指出“现在该做什么”和“点哪里”；1280×720、1024×768 没有文字压住图标或工具遮挡地块。

### Phase 2：让菜园像可探索的基地

- [ ] **P2-1 场景层次**：给 `FarmWorld` 增加可复用的装饰层（路径、草丛、围栏、旗帜、石头），按地块/建筑留出安全区，不吞掉手指事件。
- [x] **P2-1a 世界主任务旗标**：复用 `PlotView.draw_task_beacon()`、`FarmWorld` 和主任务的 icon/tint；成熟/照料/播种等目标落到唯一地块，交单落到真实订单板，既不改变 `bed_under()` / `facility_under()`，也不会在面板上留下旧旗标。16:9 与 4:3 已实机截图、触控验证。
- [ ] **P2-2 地块成长感**：在 `PlotView` 上以统一的土壤边缘、湿润色、成熟光点、稀有金色状态表达进度；继续复用现有作物状态。
- [ ] **P2-3 建筑故事点**：仓库、厨房、订单板各增加一条短、图形化的“去这里能做什么”提示；入口来自建筑而非新浮层。
- [x] **P2-4 真实收纳反馈**：依据 `Barn.store_harvest()` 的既有 `stored / spilled` 回执，把部分收纳拆为仓库与溢出篮两段飞行；溢出篮锚点固定，作物行横向扩展也不会带偏同一笔刷的反馈。`GardenTouchProbe` 与 `FarmWorldProbe` 已走真实满仓路径验证。

验收：满仓收菜时，视觉目的地和数字变化一致；普通地块、需照料地块、成熟地块、金色地块一眼可区分。

### Phase 3：丰收关的“会玩懂”反馈

- [x] **P3-1 正确的手势演示**：教程、真实触控探针与 `Gesture.satisfied()` 共用 `Gesture.demo_path()`；直线、横切、往返和旋转轨迹均由当前作物参数生成，并已由纯逻辑和真实触控验证。
- [x] **P3-2 一个活动指针**：手持作物后，三级提示都指向篮子；重复误触会替换旧手指，正确入篮立即清理过期提示。
- [x] **P3-3 低动态完整路径**：在 `HarvestTarget` 和 `TutorialDirector` 中沿用设置，关闭大位移动画时保留静态高亮、落点和清楚的手持态；`HarvestTouchProbe` 已在 16:9 / 4:3 下验证静态教程轨迹、手持态、唯一篮子指引与入篮勾。
- [x] **P3-3a 共享英雄手势**：把原先圆条加圆点的“棒棒糖手”替换为清楚的食指、拇指、手掌与蓝色袖口；指尖通过 `guide_hand_tip()` 对齐实际动作终点，并复用到教程、冒险提示与技能栏。16:9 / 4:3 实机截图已复核。
- [ ] **P3-4 订单叙事**：复用现有顾客头像、订单条和奖励逻辑，强化“谁想要什么—我交到了—他开心了”的三拍反馈。

验收：孩子首次看到复杂作物能照演示完成；单次空点不产生多根手指；低动态模式下仍知道下一步和物品去向。

### Phase 4：素材包、质检与小范围试玩

- [ ] **P4-1 风格试片**：只导入/生成小样板，审查轮廓、缩放、透明边、色彩和授权记录后再扩量。
- [ ] **P4-2 小屏可读性**：按 48px、72px、96px 三档检查作物、工具、奖励和状态图标，不靠小字补信息。
- [ ] **P4-3 回归截图**：菜园、市场、丰收关各出 16:9 与 4:3 截图；与基线对比层级、遮挡、对比度和低动态状态。
- [ ] **P4-4 儿童观察清单**：让 5–8 岁孩子（或模拟任务）完成“浇水、收一次菜、交一单、找到溢出篮、完成一个复杂手势”；记录停顿点而非只问喜不喜欢。
- [ ] **P4-5 中文展示字试片**：只在标题和奖励徽章做一屏试验，候选为 [ZCOOL KuaiLe](https://github.com/googlefonts/zcool-kuaile)（SIL OFL 1.1）；正文仍保持当前清晰字体。验收中文字符完整、目标尺寸不糊、不挤压按钮。

## 每次迭代的交付门槛

1. 先复用组件并写清数据/事件从哪里来；若确需新增组件，必须能在菜园和丰收至少两处复用，或说明为什么只能一处。
2. Godot 探针使用独立 `user://` 沙盒，**串行**运行，不能和其他探针共用存档。
3. 运行相关逻辑、触控和静态检查；视觉改动额外生成 16:9 与 4:3 截图。
4. 不以“增加更多按钮/更多文字”解决看不懂的问题；先改图标、位置、对比度、动作和反馈。
5. 每个实际引入的外部素材都可追溯，且在目标尺寸下风格一致。

## 推荐实施顺序

`P0 可信赖 → P1 看得懂 → P2 有自己的基地 → P3 玩得会 → P4 扩素材与观察验证`。

这样不会在奖励与引导尚不可靠时先做大批美术替换，也能让每一阶段独立截图、测试、回滚和验收。
