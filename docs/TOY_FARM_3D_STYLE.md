# 玩具农场 3D 美术合同

> 状态：方向规范，尚未代表某一批 3D 素材已通过评审。
>
> 适用：每日菜园、丰收挑战及两者共用的环境资产。
>
> 目标用户：5–8 岁儿童；优先平板横屏。

## 1. 目标画面

做成一组能被孩子想象成“可以拿起来玩的农场模型”的资产：圆润、清楚、颜色亲切，有真实的前后遮挡、体积和脚下接触关系。不是写实模拟农场，不是未经整理的低模原语，也不是把不同画风的 PNG 摆在同一张背景上。

画面的第一层级必须是孩子当前要做的事：成熟作物、可放入的篮子或需要照料的菜畦。地形、房屋和装饰用于说明“这是一个地方”，不能和交互目标抢注意力。

## 2. 相机与空间

- 统一固定正交 3/4 视角；源资产默认使用相同相机、相同地面方向和相同接地基准，不为每个资产单独挑好看的角度。
- 资产要能看见上表面和一段侧面；如果只看到正面轮廓，或视角低到作物像平面立牌，就不通过。
- 每个模型的原点放在真正接地处；菜根、篮底、树干底和建筑地基必须能对齐同一地面。
- 通过近中远遮挡、泥土被草缘包住、作物部分埋土和短接触影表达空间，不靠漂浮的椭圆底座补救。
- HUD 保持现有 2D 层，仍由 `UiKit` / `HeroTaskRibbon` 复用；3D 视觉不承载文字、订单或触控反馈。

## 3. 轮廓、材质与光照

- 轮廓以圆角、略有手作起伏的造型为主；可以保留温和的低模切面，但不能整屏由球体、圆柱、圆盘直接拼成。
- 表面偏哑光，粗糙度建议 `0.75–1.0`；不使用金属强高光、照片纹理、明显重复贴图或浓重颗粒噪声。
- 主光统一来自左上前方，色温偏暖；补光轻柔。脚下阴影短、软、方向一致，不能出现黑色硬块或看起来像漂浮的长影。
- 草地使用中等明度的自然绿，不发荧光；土壤是暖褐色但保留亮面变化；作物负责提供清楚的红、橙、黄等识别色。
- 可交互目标的边缘比环境清晰；远景降低饱和度和对比度，近景不要靠深黑描边勾一圈。

## 4. 第一套资产范围

先做一个可同屏审核的小套件，不批量替换现有作物：

1. 一种已成熟作物（优先胡萝卜或番茄），至少包含正常态与被拿起态的画面处理；
2. 一段可复用的软土菜垄和草缘，作物能明显从土里长出来；
3. 一只开口清楚、有真实篮沿/提手体积的收菜篮；
4. 一簇与同一套风格一致的短草，以及一段很淡的远景地形。

素材须来自同一套源资产，或由同一美术规范制作并经过同屏校色。单独一只好看的作物模型不构成资产包，也不能据此切换整页风格。

建议保存可编辑源文件和运行时格式（`.blend` / `.glb`）；若最终采用正交预渲染精灵，另保存透明 PNG、接地 pivot 说明和导出清单。不要把整张环境烘成单张图片。

## 5. 项目集成边界

- 先用 3D 制作、2D 运行的 2.5D 资产验证材质与构图；真正的模型输入、订单、手势、存档和相机仍由当前 Godot 2D 组件负责。
- `HarvestTarget` 仍是唯一作物目标，`HarvestBasket` 仍是唯一篮子规则；`FarmWorld` / `FarmCamera` / `PlotView` 仍是菜园唯一布局、命中与地块状态来源。
- 视觉替换必须读取既有组件的位置和状态，不得新增一套 3D 点击、射线、订单或生长判断。
- runtime `SubViewport` 仅在同屏美术过关后、且确实需要动态受光/轻动时另做可移除试片；它不能成为接入美术资产的捷径。
- 项目当前是 Godot 4.7 + GL Compatibility；先用简单正交渲染路径。无明确收益前不引入 Three.js，也不全局切换渲染器。

## 6. 评审与通过门槛

同一张评审图里必须同时出现作物、土垄/草缘和篮子，不能逐件单独展示后就宣布通过。至少审以下四种状态：

- 16:9 丰收普通态；
- 4:3 丰收普通态；
- 手持作物态；
- 菜园中的地块/同风格地标缩略预览。

逐项检查：是否像同一套玩具、作物有没有扎根、篮口能否读出来、草地有没有变成空白色板或噪声、四边裁切是否安全、关键物体在 72–96px 下仍能区分。任何一项明显像“贴上去”、悬空、材质跳变或误导点击，都退回资产/构图，不接产品页。

## 7. 明确拒绝的试片特征

- 用球体山、圆盘地块、圆柱篮子堆出整页场景；
- 无来源贴图、强噪声草地或整片荧光绿；
- 3D 模型漂在用户提供的水粉背景上；
- 篮子只有圆筒，没有开口、篮沿和把手的空间关系；
- 为了展示 3D 重做儿童已经能正确使用的二维触控交互。
