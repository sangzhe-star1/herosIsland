## 冲突一：现在有**两套**衣柜，而且互不相通

| | 英雄小屋（在用） | 星光礼物屋（写好了，没接 UI） |
|---|---|---|
| 拥有的东西存哪 | `rewards.outfits`（id 数组） | `data.shop.owned` |
| 穿着的存哪 | `profile.outfit` | `data.shop.equipped` |
| 槽位名 | `hat / face / suit / back / colour` | `head / body / back / hands / feet` + `pal / ride / fx / action` |
| 商品和价格 | `data/rewards.json` 的 `outfits`（17 件） | `data/shop_items.json`（21 件） |
| 谁在读 | `hero_house.gd` | 只有 `tests/shop_probe.gd` |

两边只共用一个钱包（`rewards.coins`）。**`back` 是唯一撞名的槽位，而且里面装的
是不同的东西**（旧的 `cape_red` / 新的 `cape_star`）。

`docs/SHOP_PLAN.md` 第六节当时定的是"换装移交新商店，英雄小屋只保留选角色和贴纸
墙"。你现在的需求正好相反——把英雄小屋做成换装屋。**我建议按你现在的方向来，
并且反过来合并：以英雄小屋为唯一换装入口，`data.shop` 的槽位命名和数据结构胜出
（它有 `unlock_condition`、`character_compatibility`、`slot`，旧的没有），旧的
17 件迁移过去。**存档迁移必须写，否则孩子已经买的衣服会消失——上周怪兽图鉴换 id
时就是这个坑。

## 冲突二：`hands` 和 `feet` 现在**画不出来**

`scripts/world/hero_art.gd` 是纯矢量代码画的英雄，它认识的部件只有：

- `hat`：crown / party_hat / cowboy_hat / cap
- `face`：bandana / sunglasses
- `suit`：dress / vest / star_robe
- `back`：cape_red / wings
- `colour`：6 套配色

**没有手，没有脚。** 已经上架的 `boots_bolt`（靴子）和 `gloves_rainbow`（手套）
今天穿上去是**什么都不会显示**。你要的鞋子分类，得先有挂点。

这也是我认为该改用图片素材的原因，见第四节。

## 冲突三：戴帽子会**把角色的头冠削掉**

`hero_art.gd:357`——穿了帽子就不画 crest。迪迦的鳍、赛罗的角是孩子认人的第一
特征，而你自己的规则写着"装扮不能遮挡角色关键识别部位：主要头部轮廓"。

现在 4 顶帽子全部违反这条。改法在第五节。

# 四、角色预览实现方式

这是整个方案里最需要你拍板的一节。

## 现状

英雄是**代码画的矢量图形**（`hero_art.gd`，899 行），按 `Shapes` 图元一层层堆
出来。它有姿势、有转圈、能按像素高度缩放。衣服也是代码画的——每加一件衣服要
在 `HeroArt` 里画一遍（穿在身上的样子）、在 `IconLibrary` 里再画一遍（卡片图
标），漏一个卡片就是空白。

## 你要用生成的图片，那就换成"挂点 + 图层"

`HeroArt` 的节点树天然适合挂东西：

```
self → _spin → _root → { _leg_back, _arm_back, _torso, _leg_front,
                         _head, _arm_front, 肩甲 }
```

这些节点**已经在跟着姿势动**。所以只要把图片精灵挂进正确的节点，衣服就自动跟着
走路、跳跃、转圈、庆祝——一行动画代码都不用写。

新增 `HeroArt.mount(slot) -> Node2D` 返回挂点，配一张偏移表：

| 槽位 | 挂到 | 图片锚点 | 说明 |
|---|---|---|---|
| `head` | `_head` | 图片底边中点 = 头顶 | 帽子 |
| `face` | `_head` | 图片中心 = 眼睛中线 | 眼镜、面罩 |
| `body` | `_torso` | 图片上边中点 = 领口 | 上衣 |
| `back` | `_root`（**在 `_leg_back` 之前**） | 图片上边中点 = 双肩中点 | 披风、翅膀、背包 |
| `hands` | `_arm_front` + `_arm_back` 各一份 | 图片中心 = 手心 | 手套（左右各一，右手镜像） |
| `feet` | `_leg_front` + `_leg_back` 各一份 | 图片底边中点 = 脚底 | 鞋（左右各一） |

`hands` / `feet` 是新槽位，需要在 `hero_art.gd` 里补两个挂点节点。这是这一节
唯一的"新骨架"工作，比重画整个英雄小得多。

**每个槽位一张偏移+缩放表**放在新文件 `data/character_slots.json`，逐件微调
（大概每件 3 个数字：x、y、scale）。我会写一个预览工具，把 24 件逐件挂上去截图，
偏移不对的一眼能看出来。

## 关于"左右拖动看正面/左侧/背面/右侧"

**这一条我建议第一期不做真的四面。** 原因：矢量英雄只有一个三四分之一正面视角，
没有侧面也没有背面；要做真的四面，等于把英雄本体和 24 件衣服都再画三遍（96 张
图），而孩子能得到的是"能看到披风背面"。

第一期用**转半圈**替代，`HeroArt.spin()` 已经写好了：拖动 → 角色跟着手指转 →
松手弹回正面。视觉上是"我转动了他"，成本几乎为零。你的第三节"角色转半圈展示正面
和侧面"本来就是这个意思。

真的背面视角放到第三期，届时**只需要背饰的背面图**（披风、翅膀、背包 6 张），
因为其它槽位从背后基本看不见——这是个划算的小增量。**要不要做，那时再定。**

## 试穿不能走 `refresh_outfit()`

`SkinnedCharacter.refresh_outfit()` 读的是**存档**。试穿一件没买的东西必须不碰
存档，所以要加一条新路：

```gdscript
# SkinnedCharacter
func preview_outfit(overrides: Dictionary) -> void   # 临时覆盖，不写存档
func clear_preview() -> void                         # 回到存档的样子
```

`preview_outfit` 里做的事：把 `_art.outfit` 设成"存档 + 覆盖"的合并结果再
`rebuild()`。存档一个字节都不动。离开页面、切换到另一件没买的东西、按"恢复刚才"，
都走 `clear_preview()`。

**这是"试穿绝不扣费"这条规则的实现位置，也是探针要盯的地方。**

# 五、商品状态机

每件商品在任一时刻处于且仅处于一个状态：

```
                    ┌──────────────┐
                    │  LOCKED 未解锁 │   真实剪影 + 图形化解锁条件
                    └───────┬──────┘   （世界图标 / 关卡数字 / 星星数 / 徽章）
                            │  达成 unlock_condition
                            ▼
        ┌───────────────────────────────────┐
        │  BUYABLE 已解锁未购买                │  可试穿 · 显示 ⭐价格
        └───┬───────────────────────────┬───┘
            │ 点卡片                     │ 买
            ▼                           ▼
   ┌─────────────────┐        ┌──────────────────┐
   │ TRYING 试穿中     │───买──▶│  OWNED 已拥有     │  ✅ +「穿上」
   │ （不写存档）       │        └───┬──────────┬───┘
   └────────┬────────┘            │ 穿        │ 脱
            │ 换一个 / 离开          ▼          │
            └──────────────▶  ┌──────────────┐ │
                              │ WEARING 穿戴中 │◀┘  金框 +「正在使用」
                              └──────────────┘

        NEW 新获得：叠加在 OWNED / WEARING 上的一个标记，
        右上角一颗小星光，第一次看过后消失（写 data.shop.seen_new）。
        绝不用一直闪的红点。

        INCOMPAT 不兼容：叠加在任何状态上。卡片显示角色小图标 + 锁形
        +「换个英雄试试」。bluey 和照片皮肤对所有衣服都是这个状态。
```

**状态从哪来（全部是查询，不存冗余）**

| 状态 | 判定 |
|---|---|
| LOCKED | `not Shop.unlocked(entry)` |
| INCOMPAT | `not Shop.fits(entry, 当前角色)` |
| WEARING | `Shop.is_equipped(id)` |
| OWNED | `Shop.owns(id)` |
| BUYABLE | 以上都不是 |
| TRYING | UI 自己的临时变量，**不落盘** |
| NEW | `id in 目录` 且 `id not in data.shop.seen_new` 且已拥有 |

这条很重要：**卡片状态不缓存**，每次刷新重新问。缓存状态是"改了名字留下一张查
找表"那类 bug 的温床，这个项目这个月已经犯过四次。

# 六、购买和试穿流程

## 试穿（免费，0.5–1 秒）

```
点卡片
 ├─ LOCKED   → 卡片轻弹回 + 柔和音效 + 解锁条件放大一下。不试穿
 ├─ INCOMPAT → 卡片轻弹回 + 角色图标闪一下 +「换个英雄试试」
 └─ 其它
     0.00s  卡片向上弹 8 px（Juice.pop）
     0.05s  商品图从卡片飞向角色对应部位（Tween，抛物线）
```

## 补 3 · 技术验证：图层挂骨头，跑通了

方案第四节说"把图片挂进 `HeroArt` 的骨骼节点，衣服就自动跟着姿势动"。
**这是全案最大的技术风险，所以我先做了一个一次性验证，不是写在纸上。**

结果（截图 `outfit_spike.png`）：一个迪迦，穿上救援头盔 + 救援制服 + 救援喷射包
+ 闪电靴 + 救援手套，摆四个姿势——站着、走路、欢呼、跳起来。

**衣服全部跟着动，一行动画代码都没写。** 手套跟着手臂抬起来，靴子跟着腿跳起来，
喷射包在身后。

验证过程里挖出三件事，都写进方案：

1. **成对的鞋和手套必须从中间切开。** 第一次没切，结果一只脚上四只靴子。用
   `AtlasTexture` 取左右半张就行，不用改图。
2. **素材是按"图标比例"画的，不是"穿在这个身体上的比例"**，直接挂上去帽子比人
   还大。这不需要重画，只要每件三个数字（宽度、锚点 x、锚点 y）——正是
   `data/character_slots.json` 的用途。第一版数字已经量出来了（英雄总高 232 单位，
   头宽约 102）：

   | 槽位 | 宽度 | 锚点（骨骼局部坐标） |
   |---|---|---|
   | head | 104 | (0, −99) |
   | body | 92 | (0, −78) |
   | back | 104 | (0, −96)，插在最底层 |
   | feet | 30 | (±2, +40)，左右各半张 |
   | hands | 26 | (±2, +48)，左右各半张 |

3. **帽子和头冠可以共存**（冲突三的解法）。截图里迪迦的鳍从救援头盔顶上露出来，
   看着像是故意设计的。不用改 `hero_art.gd:357` 的逻辑，只要把帽子往上挪一点、
   不要压到眼睛就行。**第一版我把头盔放低了，正好盖住眼睛，违反你自己的规则；
   调高 25 个单位就对了**——这类问题只有真渲染才看得见。

## 补 4 · 形象与皮肤选择（你这次新加的要求）

现在选角色是屏幕第五排的一行小卡片，六个角色，每个角色高约 190 px。
换装的时候孩子看的是六个小人，不是一个大英雄。

### 改成：展示台下方的大头像转盘

```
        ╭──────────────────────────────╮
        │                              │
        │          大 英 雄             │
        │       （展示区 75%）           │
        │                              │
        ╰──────────────────────────────╯
     ╭───╮  ╭───╮  ╭━━━╮  ╭───╮  ╭───╮
     │迪迦│  │赛罗│  ┃光の┃  │葛雷│  │尤莉│      ← 圆形大头像 110px
     ╰───╯  ╰───╯  ┗━━━┛  ╰───╯  ╰───╯         当前那个抬高 12px + 金环
```

点一下换英雄：旧的走出画面（`walk()` 已有）→ 新的从天而降
（`entrance()` 已有，本来就是这个动作）→ 落地一圈冲击波。**两个动作都是现成的。**

### 关键改动：每个英雄记住自己的衣服

现在 `profile.outfit` 是**全局**的——给迪迦戴上王冠，切到赛罗，赛罗也戴着。
对孩子来说这是"只有一个人换了皮肤"，六个角色不像六个角色。

建议改成 `data.shop.equipped` 按角色分：

```json
"equipped": {
  "tiga":  {"head":"helmet_rescue", "body":"suit_rescue", ...},
  "zero":  {"head":"crown_brave",   "body":"armor_castle", ...},
  ...
}
```

这样"换英雄"本身就成了换装玩法的一部分：**五个英雄可以打扮成五个完全不同的样子，
随时切换**。存档迁移把现有的那一套复制给每个角色，一件不丢。

### 皮肤 = 角色 × 配色 × 伙伴

| 轴 | 数量 | 说明 |
|---|---|---|
| 英雄 | 5 | 迪迦、赛罗、光之英雄、葛雷、尤莉 |
| 配色 | 8 | 星空蓝、阳光黄、彩虹、薄荷绿、樱花粉、勇气红、梦幻紫、云朵白 |
| 伙伴 | 8 | 光球、蜜蜂、小猫、小狗、狐狸、云朵鸟、小飞龙、机器人 |

光是"英雄 × 配色"就有 **40 种基础形象**，一件衣服都不用买。配色按你第十节的要求
分部位上色（披风色、背包色、鞋色、特效色、展示台灯光色分开），**不动迪迦和赛罗的
关键识别花纹**。

### 小狗（bluey）怎么办

`bluey` 用的是另一套渲染器，`refresh_outfit()` 对它是空操作——**它永远穿不了任何
衣服**，但现在商品照样显示可买。孩子花 35 星星币买一顶帽子，穿上去什么都没有。

不要用灰色禁用。建议：选中小狗时，衣柜整片换成一张卡片——

> 🐶 **小狗不用穿衣服，它有毛！**
> 不过它可以有玩具伙伴 →

然后把分类切到"伙伴"（伙伴不穿在身上，站在旁边，小狗完全可以有）。
**孩子得到的是一个解释和一条出路，不是一堵灰墙。**

照片皮肤（`photo/tiga_photo.tres`、`zero_photo.tres`）同理，而且它们本来就没有
接进 `characters.json`，先不管。
